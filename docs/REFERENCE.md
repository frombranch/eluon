# 참조표

`CLAUDE.md` 본문에서 빼낸 조회용 표입니다. 규칙이 아니라 **찾아보는 것**이라
작업 중 필요할 때만 엽니다. 규칙은 `CLAUDE.md`, 실패 사례는 `FAILURES.md` 입니다.

## 자산 카탈로그

### 페이지를 이루는 덩어리

`header-gnb-lg`(로고·주 메뉴·주요 액션) · `hero-split-lg`(제목·리드·액션 + 지표 레일, **사진 없음**) ·
`hero-media-lg`(전면 사진 위에 제목·리드·액션, 스크림 필수) · `section-header-md` ·
`cta-band-lg`(페이지에 하나) · `list-row-md` · `form-field-md` · `footer-lg`.

이 덩어리들은 콘텐츠 폭 자체가 규격이라 `spec.width` 가 `container.max` 를 가리킨다.

> **히어로는 둘 중 하나만 쓴다.** 수치를 앞세우면 `hero-split-lg`, 장소·사진을 앞세우면 `hero-media-lg`.
> 둘을 같이 놓지 않고, `hero-split-lg` 밑에 사진을 덧붙이지도 않는다.

### 페이지의 뼈대 순서

```
header-gnb-lg → 히어로 → 본문 섹션들 → cta-band-lg → footer-lg
```

**히어로는 GNB 바로 다음이다.** 검색 바·필터·예약 위젯 같은 **도구는 히어로 위가 아니라 아래**에 둔다.
사람은 "여기가 어디인지" 먼저 알고 나서 조작한다.
**브리프의 섹션 나열 순서를 배치 순서로 읽지 않는다**(`FAILURES.md#brief-order`).

### 아이콘

**Lucide** 한 세트만. 24×24 기준(2의 배수) · `fill:none` 선만 · 선 굵기 **1.2** ·
불투명도 0.7 · 색은 `currentColor`. 채운 아이콘은 쓰지 않는다.

```html
<script src="https://cdn.jsdelivr.net/npm/lucide@latest/dist/umd/lucide.min.js"></script>
<style>[data-lucide]{fill:none;stroke:currentColor;stroke-width:1.2;opacity:.7}</style>
```

## 구조 · 경로 · 빌드

```
manifest.json          ← 단일 진실 공급원. 항상 여기부터
                          spec = 토큰 이름 · specByTheme = 테마별 실제 수치
tokens/core.json       ← 브랜드·업종 중립 파운데이션
tokens/theme-*.json    ← 고객사 값
recipes/components.py  ← 컴포넌트 정의. spec 이 곧 CSS 이고 곧 이미지다
docs/tokens/*.css      ← [생성됨] 테마별 CSS 변수
index/sheet-*.png      ← [생성됨] 엘루온 시트
```

**사람이 고치는 것은 `tokens/` 와 `recipes/` 둘뿐이다.** 나머지는 전부 생성물이다.

**자산을 쓰는 3가지 경로** — **A 코드로 재현**(권장): 토큰 CSS 링크 + spec 으로 실제 컴포넌트를 만든다.
**B 이미지 URL 참조**(목업): `cdn.<theme>` 값을 그대로 `<img src>` 에. 손으로 URL 을 조립하지 않는다.
**C 저장소 클론**(단일 파일): 토큰 CSS 를 `<style>` 에 통째로, 이미지는 base64 로.

**신규 컴포넌트 추가** — `recipes/components.py` 에 dict 를 더하고 파이프라인을 돌린다.

```bash
python3 scripts/build_tokens.py && python3 scripts/render.py \
  && python3 scripts/build_manifest.py && python3 scripts/build_pb_manifest.py \
  && python3 scripts/make_montage.py && python3 scripts/build_measure.py \
  && python3 scripts/build_docs.py && python3 scripts/build_guide.py
```

⚠️ 그룹을 추가하면 고쳐야 할 곳이 **다섯 곳**이다(`FAILURES.md#group-enum`).
⚠️ 버전을 올리면 **수기 문서 넷**도 같이 고친다(`FAILURES.md#version-bump`).

**일관성 QA** — 테마를 먼저 확정하고 `specByTheme.<테마>` 와 항목별로 대조한다.
반응형·모션·이미지도 대조한다. `자산ID / 기대값 / 실제값 / 위치 / 심각도` 표로 보고하고,
**자동 수정하지 않는다. 표만 낸다.**

## 업종별 「빠지면 안 되는 핵심 흐름」

CLAUDE.md §A-T1-2 에서 업종을 지목한 뒤 이 표의 그 줄을 펼칩니다.
**이 줄의 부품이 대조 1순위입니다.**

| 업종 | 핵심 흐름 | 라이브러리 |
|---|---|---|
| 호텔·숙박 | 검색(지점·기간·인원) → 요금 비교 → 객실 선택 → 정보 → 결제 → 조회 | 표·카드·폼 말고 **거의 없음** |
| 커머스 | 탐색 → 필터 → 상세(옵션·재고) → 장바구니 → 결제 → 배송 조회 | 장바구니·옵션·수량 **없음** |
| 미디어 | 목록 → 상세 → 관련·연재 → 구독 | 본문 조판 **없음** |
| 채용 | 탐색 → 필터 → 공고 → 지원서 → **파일 첨부** → 진행 조회 | 업로드 **없음** |
| 금융 | 비교 → 시뮬레이션 → 약관 동의 → 신청 → 심사 | 계산기·체크박스·금액 입력 **없음** |
| 교육 | 탐색 → 커리큘럼 → 신청 → 결제 → 진도·수료 | 일정표·진도 **없음** |
| 병원 | 진료과 찾기 → 의료진 → **시간 슬롯 예약** → 문진 → 방문 안내 | 슬롯·주간 일정표 **없음** |
| B2B·기업 | 신뢰 확인 → 솔루션 → 자료 다운로드 → 문의·견적 | **대부분 있음** — 원래 겨냥한 업종 |

⚠️ 「라이브러리」가 "없음"인 업종은 **테마만 갈아끼워 시작할 수 없다.** 자산 신설이 먼저다.
표에 없는 업종이면 신호로 흐름을 직접 적고, 이 표에 한 줄 추가할지 사람에게 제안한다.

## 반응형 범위표

| 축 | ≥1024 | 768–1023 | 480–767 | <480 |
|---|---|---|---|---|
| 컨테이너 | `container.max` 가운데 | 100% | 100% | 100% |
| 좌우 거터 | `container.gutter` | `container.gutter` | `gutterMd` | `gutterSm` |
| 12열 격자 | 설계대로 | 6/6 또는 전폭 | 전폭 1열 | 전폭 1열 |
| 카드 그리드 | 3–4열 | **2열** | 2열 | 1열 |
| 섹션 상하 | `section.padY` | `section.padY` | `padYMd` | `padYSm` |
| 내비 | 가로 GNB | 가로 GNB | `menuNav` | `menuNav` |
| 활자 | 그대로 | 그대로 | 그대로 | display1·heading1 **한 칸 내려** |
| 누를 것 | ≥24px | ≥24px | ≥`touch.min` | ≥`touch.min` |
| `*-lg` 버튼 | 내용 폭 | 내용 폭 | 폭 100% | 폭 100% |
| **풀블리드 섹션** | 뷰포트 100% · 안쪽 `bleed.inset` | 100% · `bleed.inset` | 100% · `bleed.insetMd` | 100% · `bleed.insetSm` |
| **풀블리드 안 글자** | `stage.contentMax` | `stage.contentMax` | 100% | 100% |
| **스테이지 높이** | `stage.height` (min `stage.minHeight`) | `stage.heightMd` | `stage.heightSm` | `stage.heightSm` |
| **겹침** | spec 값 그대로 | 한 단계 내려 (`lg`→`md`) | **0. 풀고 세로로 쌓는다** | 0 |

> 아래 네 행은 `media-led` 를 선언했을 때만 씁니다(CLAUDE.md §E-12).
> **풀블리드는 컨테이너 규칙의 예외가 아니라 두 번째 컨테이너입니다.**
> `container.max` 는 글자가 놓이는 폭이고 풀블리드는 면이 놓이는 폭입니다.
> 좌측 정렬 풀블리드는 안쪽에 `container.max` 를 다시 세웁니다 — 글자 시작선이 위아래 섹션과
> 어긋나면 전폭으로 편 것이 아니라 밀린 것으로 보입니다.
> **겹침이 있으면 z-index 는 다섯 층뿐입니다** — 사진 0 · 스크림 1 · 스테이지 글자 2 ·
> 겹침 패널 3 · 투명 헤더 10. 이 밖의 값을 만들지 않습니다.

## 스크림 여섯 종류

| 토큰 | 언제 |
|---|---|
| `--media-scrim-bottom` | 글자가 하단 (기본. `--media-scrim` 은 이것의 별칭) |
| `--media-scrim-top` | 투명 오버레이 헤더 전용. 로고·메뉴만 읽히면 된다 |
| `--media-scrim-edge` | 위에 투명 헤더 + 아래 겹침 패널. 가운데는 사진 그대로 |
| `--media-scrim-even` | **가운데 정렬 제목.** 얕고 균일 |
| `--media-scrim-side` | 글자가 좌측 절반. 사진 주제가 우측일 때 |
| `--media-scrim-plate` | 그라디언트로 못 잡을 때의 대피로. 글자 상자에만 깐 면 |

## 페이지 유형별 판정선

첫 화면 사진 면적 ≥ 뷰포트의 **70%** · 페이지 전체 사진 면적 ≥ **40%** ·
사진 크기 단계 ≥ **3종** · 풀블리드 섹션 **2~4개**(1개면 히어로만 크고 나머지가 죽고,
5개 넘으면 리듬이 없다) · 사진 위 글자 **≤ 3줄 · 한 줄 40자** ·
히어로 제목 굵기 **≤ 400**(굵기는 테마가 정한다 — 시안에서 `font-weight` 를 직접 쓰지 않는다).

| 유형 | 인상을 만드는 1순위 | 14번 면적비 하한 | 15번 활자 단계 |
|---|---|---|---|
| `document` | 활자와 표 | 없음 | **5단계 이상** |
| `media-led` | **사진 면적** | **35%** | 4단계 |

CLAUDE.md §E-12 에서 유형을 선언한 뒤 이 표로 판정합니다.

## 그리드 배분 목록

12열을 어떻게 나눌지. **이 목록 밖의 배분을 만들지 않습니다**(CLAUDE.md §E-13).

| 배분 | 언제 | 태블릿(768–1023) |
|---|---|---|
| `6/6` | 대등한 둘. 사진↔글, 전후 비교 | 6/6 유지 |
| `7/5` | 글이 주인공, 오른쪽에 보조(지표 레일·요약) | 6/6 |
| `5/7` | 사진이 주인공, 왼쪽에 짧은 글 | 6/6 |
| `8/4` | 본문 + 좁은 사이드(목차·필터) | 전폭 1열 |
| `4/8` | 좁은 라벨 + 넓은 내용(정의 목록형) | 전폭 1열 |
| `4/4/4` | 대등한 셋. 가치·특징 | 6/6 + 1 |
| `3/3/3/3` | 대등한 넷. 카드 그리드 | 6/6 |
| `오프셋` | 왼쪽 1~2열을 비우고 시작. 장 전환에 한 번 | 오프셋 해제 |

**좌우 분할을 연달아 쓸 때는 배분을 뒤집습니다** — `7/5` 다음은 `5/7`.
같은 쪽에 사진이 세 번 연속 오면 페이지가 한쪽으로 기웁니다.
**오프셋은 페이지에 한 번까지.** 두 번 넘으면 기준선이 사라져 밀린 것으로 보입니다.

## 섹션 폭 단계

| 토큰 | 값 | 무엇에 |
|---|---|---|
| `container.narrow` | 720 | 글만 있는 섹션. 읽는 폭 |
| `container.max` | 테마마다 다름 | 기본 |
| `container.wide` | 1440 | 갤러리 · 넓은 표 |
| 풀블리드 | 뷰포트 100% | `media-led` 선언 시에만 |

**한 페이지에서 2단계 이상을 씁니다.** 전부 같은 폭이면 형태를 아무리 바꿔도 리듬이 없습니다.
**글자 블록의 왼쪽 시작선은 폭이 달라도 같아야 합니다** — `narrow` 를 가운데 정렬로 두면
위아래 섹션과 어긋나 밀린 것으로 보입니다.
