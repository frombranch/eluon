# 프롬프트 01 — Eluon으로 시안 만들기

가장 많이 쓰는 프롬프트입니다. `<>` 부분만 바꿔서 씁니다.

---

## A. 기본형 — 코드로 재현 (권장)

이미지를 붙이는 게 아니라 **토큰 CSS + spec으로 실제 컴포넌트를 만듭니다.**
결과물이 살아있는 화면이라 반응형·상태·접근성까지 그대로 이어집니다.

```
Eluon 디자인 시스템으로 <화면 이름> 시안을 만들어줘.

시스템: https://github.com/frombranch/eluon
테마: eluo

순서 — CLAUDE.md §A 관문을 순서대로 통과해.
각 관문 산출물을 내기 전에 다음으로 넘어가지 마.

G0 무슨 일인지 (고객사/자사 · 신규/리뉴얼 · URL · 산출물)
G1 테마 확정 ($status 와 실측 안 된 축 목록을 함께 내)
G2 자산 대조 — 고객사 건이면 필수
   이 사이트가 무엇으로 먹고사는지 먼저 한 문장으로 말하고, 근거 신호 3개를 대.
   그 흐름을 결제 직전까지 실제로 밟아 보고, 부품을 manifest 와 대조해 표 둘로 내.
   ⚠ 없는 것에 핵심 흐름 부품이 하나라도 있으면 거기서 멈추고 나한테 보고해.
     두 자산을 겹쳐 "비슷하게" 만드는 것은 대체가 아니라 신규 제작이야. 하지 마.
G3 ②/③ 분리 — 그대로 가져갈 축과 바꾸자고 제안할 축을 표로 갈라.
   ③(제안)이 3건 미만이면 통과가 아니야. 판정선은 CLAUDE.md §A-G3 에 있어.
G4 구성 계획 — 섹션표(순서/섹션명/자산ID/형태/앞 섹션과 왜 다른가)를 내고 승인받아.
   형태가 서로 다른 것이 3종 이상이어야 해. 여기까지 코드를 쓰지 마.
G5 조립 — 단일 HTML.
   - <link>로 docs/tokens/eluon-<테마>.css 를 불러오고, 색은 전부 var(--color-*) 로.
   - 수치는 manifest 의 specByTheme.<테마> 값 그대로. 바꾸지 마.
     (spec 은 토큰 이름이라 숫자가 아니야. 실제 px 는 specByTheme 에 있어.)
   - 자산을 놓기 전에 foundationByTheme.<테마> 를 읽어 — layout 이 폭·그리드·여백을,
     typography 의 role 이 어느 자리에 어떤 활자를 쓸지 정해.
     크기·간격·시간을 숫자로 쓰지 말고 토큰을 써.
   - manifest 에 없는 색·라운드·폰트를 새로 도입하지 마.
G6 제출 전 점검 — CLAUDE.md §B 체크리스트 25항목을 표로 돌려서 결과 하단에 붙여.
   실패가 하나라도 있으면 제출하지 말고 알려줘.

결과 하단에 남길 것 — 사용한 자산 ID 목록 · 관문 통과표 · specByTheme 에서
벗어난 부분과 이유 · 범용 이미지 출처와 "납품 시 교체 필요" 한 줄.

화면 조건
- 대상: <B2B 채용 담당자 / 일반 소비자 / ...>
- 목적: <무료 체험 신청 전환>
- 섹션: <히어로 / 3단 밸류 / 사례 / 최종 CTA>
- 폭: 1440 데스크톱 기준
```

## B. 엘루온 시트 첨부형 — 탐색 단계

`index/sheet-eluo.png` 한 장을 첨부하고:

```
첨부한 시트가 이 테마가 쓸 수 있는 자산 전부야.
<화면 이름>을 짜려는데 이 안에서만 골라서 구성안을 만들어줘.

- 섹션별로 어떤 ID를 쓸지 표로 (섹션 / 자산 ID / 이유)
- 시트에 없어서 새로 만들어야 하는 건 따로 목록으로
- ⚠ 없는 것을 있는 자산 두 개를 겹쳐 "비슷하게" 만들지 마. 그건 신규 제작이야
- 아직 코드는 쓰지 마. 구성안만.
```

## C. 고객사 테마로

```
<고객사> 사이트로 테마를 떠줘. URL: <https://...>

⚠ 색·치수만 뜨지 마. CLAUDE.md §A-G2 자산 대조를 반드시 함께 해.
  업종이 바뀌면 자산 목록 자체가 바뀐다 — 그게 이 단계의 절반이야.

1. G2 먼저 — 이 사이트가 무엇으로 먹고사는지 한 문장 + 근거 신호 3개.
   그 흐름의 부품을 manifest 와 대조해 「있는 것 / 없는 것」 표 둘로 내.
   없는 것에 핵심 흐름 부품이 있으면 멈추고 보고해. 유사 자산으로 메꾸지 마.
2. 그다음 값 실측 — computed style 로 색·활자·치수·라운드·컨테이너.
   루트 폰트 크기를 두 배로 올려 다시 재고 rem 값과 고정 px 를 구분해.
3. 산출: tokens/theme-<가명>.json
   - 테마 id 는 가명으로. 저장소가 public 이라 고객사가 드러나면 안 돼.
     브랜드 전용 서체 이름도 적지 마 — 그것 하나로 회사가 특정돼.
   - $status · $derived · $measured 를 채워. 무엇을 옮기고 무엇을 안 옮겼는지 적어.
   - 대비비를 전부 계산해서, 기준 미달값은 기준 없는 자리로 내리고 파생값을 넣어.
   - 정렬·풀블리드·겹침 같은 구조는 토큰으로 안 오니 rules 에 문장으로 적어.
4. 업종 자산이 필요하면 core 가 아니라 pack 에 만들자고 제안해.
   그리고 eluon.config.json 의 sites.<테마>.requiredAssets 에 무엇을 적을지 알려줘.
```

## D. 외부 링크 없이 단일 파일로 넘길 때

```
결과물을 파일 하나로 넘길 거야. 외부 리소스를 못 불러오는 환경이니까
CSS 링크를 걸지 말고 이렇게 해줘.

1. git clone --depth 1 --branch v1.14.2 https://github.com/frombranch/eluon.git
2. docs/tokens/eluon-eluo.css 내용을 <style>에 인라인
3. 이미지가 필요하면 PNG를 base64 data: URI로 인라인
4. 그 상태로 단일 HTML 작성
```

## 왜 "승인 전에 그리지 마"를 넣는가

자산 ID 목록을 먼저 받으면, 잘못된 방향을 **HTML 300줄이 나오기 전에** 잡을 수 있습니다.
이 한 줄이 재작업의 대부분을 없앱니다.
