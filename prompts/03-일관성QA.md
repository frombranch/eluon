# 프롬프트 03 — 일관성 QA

구현된 화면이 Eluon 규격을 지켰는지 검사합니다.
팀 안에서 "감으로 지적하던 것"을 표로 만드는 용도입니다.

---

## A. 구현 코드 대 spec 대조

```
아래 코드가 Eluon 규격을 지켰는지 검사해줘.

시스템: https://github.com/frombranch/eluon (manifest.json 기준)
테마: eluo
대상: <파일 경로 또는 코드 붙여넣기>

규칙
- manifest의 specByTheme.<테마> / tokens 를 정답으로 본다
- 자동으로 고치지 마. 표만 낸다.

| 자산 ID | 항목 | 기대값 | 실제값 | 위치 | 심각도 |
심각도: 높음(구조·접근성) / 중간(수치 어긋남) / 낮음(취향 차)

특히 확인할 것
- 헥스값이 하드코딩된 곳 (var(--color-*) 를 써야 함)
- manifest에 없는 라운드·높이가 등장한 곳
- dont 를 위반한 배치 (예: 확인 모달 없는 danger 버튼)
- 시간이 숫자로 쓰인 곳 (.4s · 900ms — var(--motion-*) 넷만 쓴다. 280ms 가 천장)
- 스크롤 진입 페이드·카드 hover 확대·클릭할 수 없는 요소의 hover 효과
- 자동 재생에 멈춤 버튼과 matchMedia 가드가 있는가 (mouseenter 는 터치에서 안 먹는다)
- 이미지 비율이 --media-ratio-* 밖의 값인 곳, 표시 폭의 2배로 요청하지 않은 곳
- 768–1023(태블릿) 구간을 다루지 않고 넘어간 곳

마지막에 "이건 코드가 아니라 시스템을 고쳐야 한다" 싶은 항목은 따로 빼줘.
```

## B. 시안 이미지 대 라이브러리 대조

```
저장소를 클론해서 자산 이미지를 직접 보고,
첨부한 시안이 라이브러리와 어긋난 지점을 찾아줘.

git clone --depth 1 --branch v1.11.2 https://github.com/frombranch/eluon.git

- 버튼 높이·라운드·간격이 spec과 다른 곳
- 라이브러리에 없는 새 컴포넌트가 몰래 들어간 곳
- tokens에 없는 색이 쓰인 곳

각 지적마다 시안의 위치를 설명하고 대체할 자산 ID를 제시해줘.
```

## C. 접근성 점검

```
Eluon 으로 만든 <화면>의 접근성을 점검해줘. 기준은 WCAG 2.1 AA.

- 텍스트 대비비 4.5:1 / 큰 텍스트·UI 경계 3:1
- 키보드 포커스가 모든 조작 요소에 보이는가 (input-text-md-focus 의 링 규격 참고)
- 상태를 색만으로 표시한 곳이 있는가 (badge-status-sm, chip-filter-md-selected 의 dont 참고)
- 터치 타깃 44x44 이상인가 (spec 이 그보다 작으면 ::after 로 히트 영역을 넓혔는가)
- prefers-reduced-motion 에서 자동 재생이 멈추는가

지적마다 해당 자산 ID와 manifest의 dont 문장을 근거로 인용해줘.
```

## D. 라이브러리 자체 점검 (분기 1회)

```
manifest.json 전체를 훑고 Eluon 의 건강 상태를 진단해줘.

- 서로 거의 같은데 따로 존재하는 자산 (통합 후보)
- usage/dont 가 비어 있거나 모호한 항목
- status 가 draft 인 채로 오래된 항목
- 특정 그룹만 비대하고 다른 그룹은 비어 있는 불균형
- 실제 프로젝트에서 한 번도 안 쓰인 자산

각 항목에 "통합 / 문서보완 / 승격 / 폐기" 중 하나를 추천하고 이유를 한 줄로.
결정은 내가 한다. 너는 후보만 올려.
```
