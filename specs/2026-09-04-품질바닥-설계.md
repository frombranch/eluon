## 1. 왜 하는가

이 저장소는 **무엇을 놓는가**는 완벽하게 통제하고 **어떻게 움직이고 어떻게 접히는가**는 전혀 통제하지 않는다.

실제 산출물(극동호텔 메인, harbor 테마, 1042줄)을 검수한 결과 자산 규격 위반은 **0건**이었고, 결함 8건이 전부 "manifest에 답이 없는 축"에서 났다. 답이 없으면 Claude 는 지어낸다. 지어낸 값은 시안마다 다르고, 다르면 시스템이 아니다.

빠진 축은 넷이다.

| 축 | 지금 |
|---|---|
| 모션 | `semantic.motion` 없음. CSS 변수 `--motion-*` 0개 |
| 반응형 | `breakpoint.sm/md/lg` 숫자만 있고 구간별 규칙 없음 |
| UX 품질 | `CLAUDE.md` 가 전부 금지문. "좋게 만들어라" 쪽 지침 0줄 |
| 이미지 | 비율·해상도·스크림에 대한 값도 규칙도 없음 |

네 축 모두 **테마와 무관하다.** 근거: 41개 자산의 `responsiveByTheme` 값이 여섯 테마 전부 동일하다. 반응형은 이미 사실상 전역 규칙이었고 데이터가 그것을 증명한다. 그러므로 `theme-*.json` 이 아니라 `core.json` 과 `CLAUDE.md` 에 넣는다.

### 강제 수준

**토큰 + 절대 규칙.** 색·치수와 같은 위상으로 다룬다. 일관성 QA의 대조 대상에 포함되어, 어기면 표에 걸린다.

권장 수준으로 두지 않는 이유 — 지금 `.9s ease` 가 나오는 원인이 "규칙이 약해서"가 아니라 **쓸 토큰이 없어서**다. 토큰이 있어야 근본적으로 막힌다.

## 2. 모션

### 2.1 토큰 — `tokens/core.json` → `semantic.motion` (신규 그룹)

```json
"motion": {
  "duration.fast": 120,
  "duration.base": 180,
  "duration.slow": 280,
  "easing.standard": "cubic-bezier(0.2, 0, 0, 1)",
  "easing.exit": "cubic-bezier(0.4, 0, 1, 1)",
  "distance.rise": 8
}
```

**이징은 둘뿐이다.** 셋을 두면 매번 고르게 되고, 고르는 순간 규칙이 아니라 취향이 된다. `standard` 는 화면에 남는 모든 것, `exit` 는 사라지는 것.

**`duration.slow: 280` 이 천장이다.** 이보다 긴 값의 토큰은 존재하지 않는다. CSS 에 시간 리터럴을 쓰는 것을 금지하면 `.9s` 는 물리적으로 나올 수 없다.

`semantic.size` 에 한 줄 추가 (반응형과 공유):

```json
"touch.min": 44
```

### 2.2 `scripts/build_tokens.py` — 그룹 루프 신설

`--size-*` 는 px, `--bp-*` 는 px, `--text-*` 는 무단위로 그룹마다 손으로 쓴 루프가 단위를 붙인다. motion 은 **단위가 섞여** 있어 루프를 새로 넣는다. `elevation` 루프 다음, `text` 루프 앞.

```python
for key, val in sem.get("motion", {}).items():
    unit = "ms" if key.startswith("duration.") else ("px" if key.startswith("distance.") else "")
    lines.append(f"  --motion-{key.replace('.', '-')}:{val}{unit};")

# 축약형. typography 의 --type-heading1 과 같은 방식 — 매번 두 값을 쓰다 하나 빠뜨리는 걸 막는다.
mo = sem.get("motion", {})
if mo:
    std, ext = mo["easing.standard"], mo["easing.exit"]
    for name, d in (("fast", "duration.fast"), ("base", "duration.base"), ("slow", "duration.slow")):
        lines.append(f"  --motion-{name}:{mo[d]}ms {std};")
    lines.append(f"  --motion-exit:{mo['duration.fast']}ms {ext};")
```

산출:

```css
--motion-duration-fast:120ms;   --motion-easing-standard:cubic-bezier(0.2, 0, 0, 1);
--motion-duration-base:180ms;   --motion-easing-exit:cubic-bezier(0.4, 0, 1, 1);
--motion-duration-slow:280ms;   --motion-distance-rise:8px;
--motion-fast:120ms cubic-bezier(0.2, 0, 0, 1);
--motion-base:180ms cubic-bezier(0.2, 0, 0, 1);
--motion-slow:280ms cubic-bezier(0.2, 0, 0, 1);
--motion-exit:120ms cubic-bezier(0.4, 0, 1, 1);
```

`cubic-bezier(...)` 안의 쉼표는 괄호 안이라 `transition` 리스트 파싱을 깨지 않는다.

### 2.3 reduced-motion 을 토큰 CSS 가 처리한다 — 이 설계의 핵심

`to_css()` 가 `:root{}` 를 닫은 **뒤에** 붙인다.

```css
@media (prefers-reduced-motion: reduce){
  :root{
    --motion-duration-fast:1ms; --motion-duration-base:1ms; --motion-duration-slow:1ms;
    --motion-distance-rise:0px;
    --motion-fast:1ms linear; --motion-base:1ms linear;
    --motion-slow:1ms linear; --motion-exit:1ms linear;
  }
  *,*::before,*::after{
    animation-duration:1ms!important; animation-iteration-count:1!important;
    transition-duration:1ms!important; scroll-behavior:auto!important;
  }
}
```

두 겹인 이유 — 변수 재정의는 **토큰을 쓴 CSS** 를 고쳐 준다(`translateY(var(--motion-distance-rise))` 까지 포함. 이건 `!important` 규칙으로는 못 잡는다). `*` 규칙은 **리터럴을 쓴 CSS** 를 잡는다.

모든 시안이 이미 `eluon-<theme>.css` 를 `<link>` 하거나 인라인한다. 따라서 감속 대응이 **작성자의 기억력이 아니라 토큰 파일의 속성**이 된다. 시안마다 잊어버릴 여지가 사라진다.

### 2.4 `scripts/build_manifest.py` — `foundation_maps()` 에 한 줄

```python
"motion": sem.get("motion", {}),
```

manifest 를 직접 읽는 경로(CLAUDE.md 가 시키는 경로)에서도 모션이 보이게 한다.

### 2.5 테마 "미실측" 판정에 넣지 않는다

`build_pb_manifest.py` 의 `foundation_status()` 는 테마가 덮어쓰지 않은 축을 "고객사 값 아님" 경고로 프롬프트 맨 앞에 올린다. **모션은 여기서 제외한다.** 브랜드마다 재는 값이 아니라 우리 집 규칙이고, 여섯 테마 전부에 경고가 붙어 노이즈만 된다.

테마가 `semantic.motion` 을 덮어쓰는 것은 `deep_merge` 로 자동 허용되지만, 기본은 core 하나다.

### 2.6 모션 규칙 — `CLAUDE.md` §6 신규

1. **모션은 사람의 행동에 대한 대답이다.** hover · focus · press · 상태를 바꾸는 클릭에만 건다.
2. **시간을 숫자로 쓰지 않는다.** `.4s` · `900ms` 금지. `--motion-fast|base|slow|exit` 넷 중 하나다. 280ms 가 천장이다. 더 길어야 할 것 같으면 그건 모션을 넣지 말아야 할 것이다.
3. **움직일 수 있는 속성은 다섯뿐.** `opacity` · `transform` · `background-color` · `border-color` · `color`. `height` · `width` · `top/left` · `box-shadow` · `filter` 는 애니메이션하지 않는다.
4. **어디에 무엇을 쓰나**

   | 무엇 | 토큰 |
   |---|---|
   | 버튼·링크·칩·입력의 hover/press/focus 색·테두리 | `--motion-fast` |
   | 열고 닫기 — 아코디언 아이콘, 메뉴 토글, 탭 인디케이터 | `--motion-base` |
   | 화면을 덮는 것 — 모달·토스트 등장, 전면 이미지 전환 | `--motion-slow` |
   | 사라지는 것 — 모달·토스트 퇴장 | `--motion-exit` |

   `transition` 은 hover 규칙이 아니라 **기본 상태에** 건다. 그래야 돌아올 때도 같은 속도다.
5. **넣지 않는 것.** 스크롤 진입 페이드·슬라이드업, 페이지 로드 시퀀스, 카드 hover 확대·부양, 패럴랙스, 숫자 카운트업, 타이핑 효과, 무한 마퀴, 장식용 keyframes.
   섹션마다 페이드업과 카드마다 hover 확대는 "기계가 만든 화면"의 가장 흔한 표식이다.
6. **자동 재생은 조건부로만 허용한다.** 셋을 다 갖추지 않으면 쓰지 않는다.
   1. 멈춤 버튼. `mouseenter` 로 멈추는 것은 터치에서 아예 동작하지 않으므로 이를 대신하지 못한다
   2. `matchMedia('(prefers-reduced-motion: reduce)').matches` 면 시작하지 않는다
   3. 탭이 가려지면(`document.hidden`) 멈춘다

   셋이 갖춰졌을 때 사용자가 건드리지 않아도 움직이는 것은 **화면당 하나**까지다.
7. **reduced-motion 은 토큰 CSS 가 이미 처리한다.** 시안에 `@media (prefers-reduced-motion)` 을 따로 쓰지 않는다. 단 하나, **JS 자동 재생은 CSS 가 못 막는다** — 6조가 그 자리다.
8. **사용자가 건드려서 움직이는 것에는 제한이 없다.** 이 절은 움직임의 총량을 줄이려는 게 아니라, 움직임이 무엇에 대한 대답인지를 묻는다.

> §6-6 은 검토 초안의 "스스로 움직이는 것 0개"를 조건부 허용으로 바꾼 것이다. 호텔·리조트 같은 고객사가 자동 회전 히어로를 실제로 요구하므로, 전면 금지는 현장에서 조용히 무시될 규칙이 된다. 무시되는 규칙보다 지켜지는 조건이 낫다.

## 3. 반응형

### 3.1 값은 토큰, 규칙은 계약

- **값**(거터·섹션 여백·터치 최소)은 `core.json`. 시안이 임의 숫자를 지어내는 것을 막는 유일한 방법이 토큰이고, 고객사 테마가 덮어쓸 수 있어야 하며, `foundation_maps()` → `foundationByTheme` → `fnd_lines()` 경로를 타고 manifest 와 빌더에 자동으로 실린다.
- **규칙**(몇 열로 접나, 내비는 어떻게 바뀌나)은 조건 분기지 값이 아니다. 데이터로 만들면 스키마만 늘고 문장보다 길어진다. `CLAUDE.md` 산문이 맞다.

### 3.2 `tokens/core.json` → `semantic.layout` 에 3개 추가

기존 `section.padY` / `section.padYSm` 명명을 그대로 따른다. `--layout-*` 는 이미 px 로 나가므로 `build_tokens.py` 수정은 필요 없다.

```json
"container.gutterMd": 20,
"container.gutterSm": 16,
"section.padYMd": 72
```

### 3.3 범위표 — `CLAUDE.md`

키는 전부 **max-width 하향식**이다. 이 시스템에 `min-width` 미디어쿼리는 없다. `sm`=480 · `md`=768 · `lg`=1024 이고, manifest 의 `responsiveByTheme` px 키가 그 숫자다.

| 축 | ≥1024 데스크톱 | 768–1023 태블릿 | 480–767 | <480 모바일 |
|---|---|---|---|---|
| 컨테이너 | `container.max` 가운데 | 100% | 100% | 100% |
| 좌우 거터 | `container.gutter` | `container.gutter` | `container.gutterMd` | `container.gutterSm` |
| 12열 격자 | 설계대로 (7/5 · 6/6) | 6/6 또는 전폭 | 전폭 1열 | 전폭 1열 |
| 카드 그리드 | 3–4열 | **2열** | 2열 | 1열 |
| 섹션 상하 | `section.padY` | `section.padY` | `section.padYMd` | `section.padYSm` |
| 내비 | 가로 GNB | 가로 GNB | `menuNav` | `menuNav` |
| 활자 | 그대로 | 그대로 | 그대로 | display1·heading1 한 칸 내려 |
| 터치 대상 | ≥24 | ≥24 | ≥`touch.min` | ≥`touch.min` |
| `*-lg` 버튼 | 내용 폭 | 내용 폭 | 폭 100% | 폭 100% |

**활자 한 칸 내리기** — 480 미만에서 `display1` 은 `heading1` 크기를, `heading1` 은 `heading2` 크기를 쓴다. **역할은 그대로다**(여전히 그 화면의 제목이다). 새 숫자를 만들지 않고 있는 토큰을 옮겨 쓰는 것이라 §0 의 "글자 크기를 숫자로 쓰지 않는다"와 충돌하지 않는다. 본문(`body1`/`body2`)은 어느 폭에서도 바뀌지 않는다.

**터치 대상과 spec 의 충돌 해소** — `pagination.itemSize` 40 · `toggle.size` 40 · `chip.height` 36 · `control.sm.height` 36 은 전부 44 미만이다. §0 이 spec 변경을 금지하므로 **시각 치수는 그대로 두고 히트 영역만 넓힌다.**

```css
position:relative;
::after{content:'';position:absolute;inset:50% 50%;
  width:var(--size-touch-min);height:var(--size-touch-min);
  transform:translate(-50%,-50%)}
```

이 문장이 없으면 두 규칙이 서로 모순된다.

### 3.4 절대 일어나지 않아야 할 것

- 375px 에서 가로 스크롤 (기존 규칙 유지)
- 뷰포트보다 큰 고정 px 폭. 격자 자식에 `min-width:0`, 이미지에 `max-width:100%`
- 본문 16px 미만
- `min-width` 미디어쿼리. 하향식 하나로만 쓴다 — 섞으면 두 규칙이 겹치는 구간이 생긴다
- **768–1023 을 손대지 않고 넘어가는 것.** 3·4열 카드가 여기서 깨진다. 고객이 제안서를 아이패드로 연다

### 3.5 경로 표기 정정

`CLAUDE.md:14` 와 `:176` 이 `manifest.json` 의 `responsiveByTheme.<테마>` 라고 써서 최상위 키처럼 읽힌다. 실제 위치는 `assets[].responsiveByTheme.<테마>` 이고, 키는 `sm`/`md` 가 아니라 **px 숫자**다(`recipes/components.py` 의 `RESPONSIVE` 는 `sm`/`md` 로 쓰고 파이프라인이 px 로 바꾼다). 같은 문서 안에서 "md 미만"과 "768px 미만"이 대응표 없이 섞여 나온다. 경로와 대응표를 함께 적는다.

## 4. UX 기준선 — `CLAUDE.md` §7 신규

이 절은 금지가 아니라 기준이다. 아래를 지키면 규격만 맞고 허전한 화면이 나오지 않는다.

1. **한 화면에 주장은 하나.** 이 페이지가 무엇을 시키는지 한 문장으로 말할 수 없으면 섹션을 지운다. `display1` 도 주 CTA(`cta-band-lg`)도 페이지에 하나뿐이다.
2. **훑는 순서를 만든다.** 섹션은 제목 → 리드 → 내용 → (있으면) 액션 하나. 제목만 이어 읽어도 페이지가 무슨 말을 하는지 알 수 있어야 한다.
3. **아이브로우는 페이지에 최대 두 개.** 모든 섹션 머리에 대문자 라벨을 얹으면 위계가 아니라 무늬가 된다.
4. **리듬은 두 값뿐.** 섹션 사이 `section.padY`, 섹션 안 덩어리 사이 `block.gap`. 섹션마다 여백을 다르게 주지 않는다. 더 나눠야 하면 여백이 아니라 hairline(`border.subtle`) 하나로 나눈다.
5. **경계는 셋 중 하나만.** 한 요소에 테두리·배경·그림자를 동시에 쓰지 않는다. 카드가 테두리를 가졌으면 `elevation` 은 0 이다.
6. **실제 콘텐츠로 짠다.** 제목이 두 줄인 경우, 목록이 1개인 경우와 12개인 경우를 다 확인한다. "제목입니다" · lorem 으로 채우지 않는다.
7. **빈 상태를 함께 낸다.** 목록·표·검색이 있는 화면은 `empty-state-md` 로 0건 화면을 같이 만든다. 빈 화면은 사과문이 아니라 다음 행동이다 — "조건을 지우고 전체 보기".
8. **긴 값은 자르지 말고 흘린다.** 한글 제목에 `white-space:nowrap` + 말줄임을 쓰지 않는다. 두 줄까지 허용(`-webkit-line-clamp:2`)하고 그 이상만 자른다. 한 줄 고정은 숫자·날짜·금액에만. 폭 제한은 `--layout-text-measure` 를 쓴다. `44ch` · `58ch` 같은 숫자를 새로 만들지 않는다.
9. **hover 로만 알 수 있는 정보를 만들지 않는다.** 터치에는 hover 가 없다. 클릭 가능한 것은 hover 없이도 클릭 가능해 보여야 한다. hover 는 이미 보이는 것을 밝히는 데만 쓴다. **클릭할 수 없는 요소에는 hover 효과를 걸지 않는다.**
10. **포커스를 지우지 않는다.** `outline:none` 금지. `:focus-visible` 에 `--size-focusRing-width` · `--color-focusRing`. `overflow:hidden` 안의 포커스 대상은 링이 잘리므로 `outline-offset` 을 음수로 주거나 클리핑을 푼다. sticky 헤더가 있으면 앵커 대상에 `scroll-margin-top` 을 헤더 높이만큼 준다. 페이지 맨 앞에 본문 바로가기 링크를 둔다.
11. **사진 위 글자는 판을 깐다.** 요소 전체에 `opacity` 를 걸지 않는다 — 글자까지 흐려져 대비를 계산할 수 없다. 반투명 배경(rgba)에 글자는 100% 로 둔다.
12. **효과를 넣기 전에 그게 무엇을 알려주는지 답한다.** 답이 "예뻐서" 면 넣지 않는다. 이 시스템의 인상은 여백·활자·hairline 에서 나온다. 그라디언트·글라스·블러·장식 도형·아이콘 배경 원은 쓰지 않는다.

## 5. 이미지

자산 규격이 다 맞아도 사진이 흐릿하거나 비율이 제각각이면 시안은 싸 보인다. 고급스러움은 사진의 내용이 아니라 **선명도 · 비율의 반복 · 글자와의 관계**에서 나온다. 셋 다 토큰으로 못박을 수 있다.

호텔 시안의 실태 — `?w=700`·`w=900` 요청에 `srcset` 없음(2배 밀도에서 흐리다), 비율 `4/5`·`16/9`·`9/16`·`16/10` 넷을 그 자리에서 지어냄, `width`/`height`·`loading`·`decoding` 전부 없음(이미지가 들어올 때마다 레이아웃이 밀린다), `.card-portrait .thumb` 만 `radius-xl` 이고 `.card-product .thumb` 는 0.

### 5.1 토큰 — `tokens/core.json` → `semantic.media` (신규 그룹)

```json
"media": {
  "ratio.wide": "16 / 9",
  "ratio.photo": "3 / 2",
  "ratio.portrait": "4 / 5",
  "ratio.tall": "9 / 16",
  "scrim": "linear-gradient(to top, rgba(11,13,17,.72) 0%, rgba(11,13,17,.34) 38%, rgba(11,13,17,0) 72%)",
  "density": 2
}
```

**비율은 넷뿐이다.** 다섯째를 두면 다시 그 자리에서 고르게 된다. `wide` 는 썸네일·배너, `photo` 는 일반 사진, `portrait` 는 카드, `tall` 은 전면 세로.

`scrim` 은 평평한 검정이 아니라 그라디언트다. 아래는 글자가 읽히도록 덮고 위는 사진을 그대로 둔다 — 사진과 글자를 동시에 살리는 유일한 방법이다.

`density: 2` 는 "표시 폭의 몇 배로 요청하나"의 답이다. 값으로 두어야 프롬프트에서 인용할 수 있다.

`build_tokens.py` 는 `ratio.*` 와 `scrim` 을 무단위로, `density` 를 무단위 숫자로 내보낸다(`--text-*` 루프와 같은 처리). 별도 단위 분기가 필요 없다.

> 스크림 색은 core 의 `gray.1000` 계열을 리터럴 rgba 로 굳혀 둔다. 테마가 어두운 회색을 쓰든 순검정을 쓰든 스크림의 역할(글자 가독성)은 같고, 테마별로 흔들리면 사진 위 대비를 보증할 수 없다. 필요하면 테마가 `semantic.media.scrim` 을 덮어쓸 수 있다.

### 5.2 미디어 radius 는 토큰을 새로 만들지 않는다

미디어의 모서리는 **그것을 감싼 카드와 같은 값**이다. 카드가 `radius.lg` 면 썸네일도 `radius.lg`, 카드에 radius 가 없으면 썸네일에도 없다. 별도 `media.radius` 를 두면 두 값이 어긋날 자유가 생긴다.

### 5.3 이미지 규칙 — `CLAUDE.md` §8 신규

1. **비율은 `--media-ratio-*` 넷 중 하나.** 새 비율을 만들지 않는다. 한 페이지에서 같은 역할의 이미지는 같은 비율을 쓴다 — 비율의 반복이 정돈된 인상을 만든다.
2. **표시 폭의 `--media-density` 배로 요청한다.** CSS 상 400px 로 보일 이미지는 `w=800` 이다. 가능하면 `srcset` 으로 1x·2x 를 함께 준다. **흐릿한 사진이 시안을 가장 빨리 싸게 만든다.**
3. **자리를 먼저 잡는다.** 모든 `<img>` 에 `width`·`height` 속성을 주거나, 부모에 `aspect-ratio` + `object-fit:cover` 를 준다. 이미지가 들어올 때 레이아웃이 밀리면 안 된다.
4. **첫 화면 이미지에는 `loading` 을 걸지 않고 `fetchpriority="high"` 를 준다.** 나머지는 `loading="lazy" decoding="async"`.
5. **사진 위 글자는 `--media-scrim` 을 깐다.** 요소 전체에 `opacity` 를 걸지 않는다(§7-11). 글자는 100% 로 둔다.
6. **로딩 전 배경은 `surface.sunken`.** 흰 깜빡임을 만들지 않는다.
7. **한 페이지 안에서 톤을 섞지 않는다.** 밝은 실내 사진과 어두운 야경을 나란히 두지 않는다. 범용 이미지를 검색할 때 조도·시간대·색온도를 질의에 함께 넣어 한 벌로 고른다.
8. **`object-position`.** 기본은 `center`. 인물·건물은 위쪽이 중요하므로 `top` 쪽으로 준다. 얼굴이나 간판이 잘리는 크롭을 그대로 두지 않는다.
9. **`alt`.** 장식이면 빈 문자열, 정보면 무엇이 보이는지 쓴다. "이미지" · "사진" 같은 말은 쓰지 않는다.
10. **범용 이미지는 시안임을 밝힌다.** 결과 하단에 어디서 가져온 이미지인지와 실제 납품 시 교체가 필요하다는 것을 한 줄로 적는다. 고객사 실제 이미지를 이 저장소에 넣지 않는다(§5 하지 않을 것).

### 5.4 프롬프트 비용

**0줄.** 전부 `CLAUDE.md` §8 에 둔다. 이미지는 모션·반응형과 달리 호텔 시안에서 "계약을 읽고도 틀린" 축이 아니라 **계약에 아예 없던** 축이다. 계약에 넣는 것만으로 처음 적용되므로, 프롬프트에 얹어 강조할 근거가 아직 없다. 다음 시안에서도 어긋나면 그때 `blocks()` 로 올린다.

## 7. 어디에 넣나

`CLAUDE.md` 는 에이전트가 저장소에서 읽는다. 디자이너가 복사하는 프롬프트 길이에 **0** 을 더한다. `blocks()` 에 넣은 문장은 **모든** 프롬프트를 길게 만들고 사람 눈에 노출된다. 그리고 `blocks()` 의 mockup/artifact 경로는 1단계가 이미 "CLAUDE.md 와 manifest.json 을 먼저 읽어"다 — CLAUDE.md 는 이미 매번 읽힌다.

따라서 기본값은 **전부 CLAUDE.md, `blocks()` 에는 포인터만**.

### 7.1 `blocks()` 에 얹는 7줄

`CLAUDE.md` 가 매번 읽히는데도 굳이 프롬프트에 얹는 것은 **호텔 시안이 CLAUDE.md 를 다 읽고도 틀린 축**뿐이다. 저장소에 같은 판단의 전례가 있다 — `respBlock()` 의 `why` 에 "실제로 `@media` 가 하나도 없는 결과물이 나온 적이 있습니다"라고 적혀 있다.

`motionBlock()` 신규, mockup/artifact 에만:

```
모션 — 시간을 숫자로 쓰지 마. --motion-fast|base|slow|exit 넷뿐이고 280ms 가 천장이야.
  스크롤 진입 페이드·카드 hover 확대·페이지 로드 시퀀스는 만들지 마.
  reduced-motion 은 토큰 CSS 가 처리해. @media 를 따로 쓰지 말고,
  대신 자동 재생(setInterval)은 matchMedia 로 막고 멈춤 버튼을 붙여.
```

기존 `respBlock()` 말미:

```
  768–1023(태블릿)도 따로 다뤄. 3·4열 카드는 여기서 2열이야.
  누를 수 있는 것은 md 미만에서 44×44 이상. 규격이 그보다 작으면 ::after 로 히트 영역만 넓혀.
  sm 미만에서 display1·heading1 은 한 칸 내려 쓰되(→heading1/heading2 크기) 역할은 그대로 둬.
```

### 7.2 숨은 작업 — `fndBlock()`

`docs/prompt-builder.html` 의 `fndBlock()` 은 `f.layout` 을 사전에 담지만 문장이 **고정 템플릿**이다(`g["container.max"]` · `g["section.padY"]` 를 이름으로 꺼내 쓴다). 그래서 `container.gutterMd` · `container.gutterSm` · `section.padYMd` 를 `core.json` 에 넣어도 **자동으로 프롬프트에 실리지 않는다.** 거터·섹션 여백 문장을 새 키를 쓰도록 고쳐야 한다.

모션을 빌더 블록에서 값으로 인용하려면 `build_pb_manifest.py` 의 `fnd_lines()` 에도 `"motion": f.get("motion", {})` 이 필요하다. 다만 §7.1 의 `motionBlock()` 은 값을 인용하지 않고 변수명만 말하므로 이 줄은 선택이다.

## 9. 검증

1. 여섯 테마 CSS 전부에 `--motion-*` 11개 · `--media-*` 6개와 `@media (prefers-reduced-motion: reduce)` 블록이 있다
2. `manifest.json` 의 `foundationByTheme.<테마>.motion` 과 `.media` 가 여섯 테마에 다 있다
3. 문서 사이트가 빌드되고 파운데이션에 깨진 곳이 없다
4. 빌더에서 시안 제작 프롬프트를 뽑아 모션 4줄 · 반응형 3줄이 실리는지 눈으로 확인
